First release of DBaaS: managed PostgreSQL on Harvester, with each database on its own virtual machine.

- **DBaaS operator**, installed on the Harvester cluster as a Harvester Addon. API `dbaas.opencloud.wso2.com/v1alpha1`: `DBInstance`, `DBSnapshot` and `DBRestore`.
- **DBaaS UI extension for Rancher**: create and operate databases from Rancher, including snapshots, restores, OS updates and database image management.

The API is `v1alpha1` and may change in later releases.

## Requirements

- Harvester: tested with Harvester 1.9.0
- Rancher 2.15 or later, for the UI extension. Tested with Rancher 2.15.2.
- A VLAN network on the Harvester cluster that gives database VMs internet access while they are first provisioned.
- The database VM images below, uploaded to the Harvester cluster.

## Database VM images

The operator does not download images. Build them with Packer from `database/images/packer` and upload them to the Harvester cluster's `default` namespace (the operator's image namespace by default), named exactly as below. Admins can also upload them from the UI's **Database Images** page.

| Image name                         | Ubuntu          | PostgreSQL     |
| ---------------------------------- | --------------- | -------------- |
| `ubuntu-2204-postgres-v20260515` | 22.04 (default) | 15, 16, 17     |
| `ubuntu-2404-postgres-v20260701` | 24.04           | 15, 16, 17, 18 |

## Install

1. Upload the database VM images (above).
2. On the Harvester cluster, apply the attached Addon manifest: `kubectl apply -f dbaas-operator-addon.yaml`. Check it with `kubectl get addon dbaas-operator -n dbaas-system`.
3. In Rancher, as an admin: **Extensions** → ⋮ → **Manage Extension Catalogs** → **Import Extension Catalog**, with the UI extension image from the Artifacts table. Then install **DBaaS** from the **Available** tab.

See `database/INSTALL.md` for details, including upgrades and uninstalling.

## Known limitations

- Only VLAN networks are supported. Overlay (Kube-OVN) networks are not.
- After an instance's class changes, PostgreSQL keeps the previous class's `max_connections` until the instance is repaved (OS update).
- The UI's create form lists the operator's default instance classes and PostgreSQL versions. Classes or image streams changed in the operator's configuration are not offered there.
- When an OS update is available, the UI shows the operator's message rather than the current and new image revisions as separate fields.
- Scraping PostgreSQL metrics with Prometheus needs a network route from the cluster's pod network to the database VLAN.
- The Addon carries Harvester's `experimental` label.
